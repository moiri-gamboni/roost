# files/ — what each deployed file is for

Everything here is deployed by `roost-apply push` from the manifest in `scripts/roost-apply.sh` (explicit list, no globs: a new file needs a manifest line). The root `CLAUDE.md` has the one-line map; this file holds the per-file detail that only matters when editing them. Subdirectories with their own `CLAUDE.md`: `hooks/`, `scripts/`, `scheduled/`, `travel/`, `laptop/`, `private/` (README there).

## Claude Code config

- `settings.json` — **runtime-rewritten** (see root CLAUDE.md: never blanket-push, diff with `jq -S`). Carries the hook definitions (Notification + perm-mark; UserPromptSubmit usage line + turn start, plus the asyncRewake auto-resume waiter entries on UserPromptSubmit and StopFailure; Stop/StopFailure/SessionEnd/Subagent*/PostCompact lifecycle events; PostToolUse shellcheck; PreToolUse notion-write-guard + truncation-guard), the Notion `permissions.ask` gate, the cleanup policy, and `autoContinueAtUsageLimit: true`, which must stay on: with it off the app auto-opens the `/rate-limit-options` modal on every cap, and an open modal parks the waiter's queued wake until a human presses Esc (verified on 2.1.241). On, no dialog opens; the waiter's wake submits a turn, which is the built-in episode's `manual_submit` disarm, so the two never double-fire.
- `_setup-env.sh` — sourced by every `setup/` script; reads the server copy of `.env`, exports `USERNAME`, `HOME_DIR`, etc., provides `as_user()`.
- `setup/` — one script per concern, run by `deploy.sh` via `remote_script()`. `claude-config.sh` ends with a generic source-if-present hook for `private/claude-plugins.sh`, so plugin specifics stay out of the public repo. `dev-tools.sh` adds the user to `docker` and symlinks fnm's default `node`/`npx` into `~/bin`. `snapper.sh` creates the root config and converts the regenerable trees into nested subvolumes (list in the script; conversion is a reflink copy + swap, leaving `<dir>.old` for a later removal).
- `skills/` — deployed to `$CLAUDE_CONFIG_DIR/skills/`: `codex` (delegate to OpenAI Codex via `codex exec`, spends OpenAI credits not Claude limits), `html2markdown`, `havelock-api`, `humanizer`, `pastebin` (PrivateBin via pbincli), `roughdraft` (put a Markdown file in front of the user for review; the fork/install half stays in the global CLAUDE.md), `session` (the session CLI), `zotero` (batch-manipulate a Zotero library; written for the guest device, works headless here via the web API).

## Shell

- `bashrc-append.sh` / `profile-append.sh` — stubs appended to `~/.bashrc` / `~/.profile` that source `~/.bashrc.d/$ROOST_DIR_NAME.sh` (interactive and non-interactive shells).
- `shell/bashrc.sh` → `~/.bashrc.d/roost.sh` — PATH, tmux, the `agent`/`agents`/`attach` helpers. Idempotent: only the fnm init is once-per-shell, so a plain re-`source` applies a new deploy. Targets on the `main` session are written `=main`, the exact-match form: a plain `-t main` also resolves by fnmatch and then by *prefix*, so with the session killed and one grouped view alive it silently lands in `main-pixel` and the breakage stays invisible until a second view makes the prefix ambiguous. The one deliberate exception is `new-session -t main`: that flag also accepts a session *group* name, which is what lets the group rejoin work at all, and `=main` there would quietly start a second group literally named `=main`. Exports the Roughdraft env: `ROUGHDRAFT_BIND_HOST` (loopback + `tailscale ip -4`, so the review UI on `:7373` is reachable from the tailnet), `ROUGHDRAFT_TOKEN` (from `~/.config/roughdraft/token`, `0600`, generated on the box, never in the repo: Roughdraft refuses a non-loopback bind without one because its remote-document endpoints rewrite files on disk; no token file = loopback-only, the right degraded state for a fresh server) and `ROUGHDRAFT_NO_OPEN=1`.
- `tmux.conf` — the client-focus-in/out/detached and session-window-changed hooks feed `session --focus-mark` (attended time for `session time`). The two tmux-3.4 gotchas (`#{hook_client}` is the only correct client reference in a per-client hook; there is no `client_focused` format, test with `#{m:*focused*,#{client_flags}}`) are commented inline at the hook lines. A `session-closed` hook runs `lib/tmux-main-guard.sh --if-attached`, which rebuilds `main` from its session group when something kills it; `--if-attached` is what stops a teardown of the last views from resurrecting the session and with it the whole server. Status bar: the current window's `#{pane_title}` (the Claude session name) alone, plus `session #{window_index}/#{session_windows}` and the clock — the other windows are not listed, `agents` is how you switch. `renumber-windows on` is what keeps that X/Y honest, and only applies from the next window close, so a session with existing gaps needs one `tmux move-window -r -t '=main'`.

## Networking and services

- `Caddyfile` (envsubst template; `default_bind $TAILSCALE_IP`; imports `/etc/caddy/sites-enabled/*`) + `caddy-tailscale.conf` (systemd drop-in: wait for Tailscale before starting).
- `cloudflare-config.yml` — tunnel base template, deployed to `/etc/cloudflared/config.yml.base`. `lib/cloudflare-assemble.sh` reads its tunnel header and merges `~/roost/cloudflared/apps/*.yml` into the live `/etc/cloudflared/config.yml` (run by `roost-apply push files/cloudflare-config.yml`, `roost-apply --cloudflare`, or standalone). Never write the template to the live path: it clobbers the assembled ingress.
- `ntfy-server.yml` → `/etc/ntfy/server.yml` — listens `0.0.0.0:2586` (v4-only pin), auth required.
- `tailscaled-iptables.conf` — drop-in pinning `tailscaled` to the iptables backend so the travel VPN's masked fwmark has predictable Tailscale mark bits to work around.
- `sshd/50-clip-forward.conf` — `StreamLocalBindUnlink yes` for the laptop clipboard-forward socket.
- `dufs.service` — read-only (`--allow-upload`/`--allow-delete` off) on `127.0.0.1:5000`; Caddy site `sites-enabled/drop.caddy` on the Tailscale IP `:443` with the `*.$DOMAIN` Vision wildcard cert (`caddy` in group `xray`; `vision-cert-renew.service` reloads Caddy after renewal), rewriting `Content-Disposition: inline` → `attachment` so HTML/JS downloads instead of rendering.
- `privatebin/` — `conf.php` (markdown default formatter, discussion off, CF-aware rate limiting; → `/etc/privatebin/`), `php-fpm-pool.conf` (dedicated `privatebin` user; socket consumed by Caddy), `privatebin.caddy` (loopback origin `127.0.0.1:8095` + the public write gate: tunnel-tagged (`CF-Connecting-IP` present) write methods → 403), `privatebin-cloudflare.yml.tmpl` (ingress for `paste.$DOMAIN`; `deploy.sh` ensures the proxied CNAME). App at `/var/www/privatebin` (root-owned; weekly same-major updates via auto-update), pastes under `/var/lib/privatebin/data` (owner `privatebin`). The health check asserts the write gate every 5 minutes.
- `glances.service`, `ram-monitor.service`/`.timer` (30s), `btrfs-convert.sh` (rescue-mode ext4 → btrfs with `@rootfs`).
- `notion-webhook.service` — the Notion webhook receiver (`apart-research/apart-tools/notion-mirror/webhook_receiver.py`; captured from the previously hand-installed unit).
- `granola-webhook.service` — the Granola webhook receiver (`apart-research/apart-tools/granola-mirror/webhook_receiver.py`, `127.0.0.1:8097`, routed as the `^/granola` path on the hooks hostname via the `granola-hooks.yml` tunnel fragment). Primary trigger for the granola-mirror pipeline: a Standard-Webhooks-verified `note.generated`/`note.edited`/`note.access_granted` event kicks the clone's `refresh.sh --commit`, debounced, under the same flock as the fallback cron. Refuses to start without the signing secret at `~/.config/granola/webhook-secret` (written once at endpoint registration; see the receiver's docstring).
- Both webhook units: `Restart=on-failure` does not reload on file change; edit → `sudo systemctl restart <unit>`; rollback = revert the file, then restart.
- `cron-roost` — the base crontab (health checks, scheduled jobs, auto-update); app cron goes in `/etc/cron.d/${ROOST_DIR_NAME}-apps`, private mirrors in `private/cron-mirrors`.
- `lib/_hook-env.sh` — `hook_input()`/`hook_json()`, `ntfy_send()` (journald fallback), `rate_limit_ok()`, `logger -t "$_HOOK_TAG"` (`roost/<script>`); `set -uo pipefail` without `-e`. Cron-user scripts set `HOOK_DROP_TO_SUDO_USER=1` before sourcing so an ad-hoc `sudo` run re-execs as `$SUDO_USER` (same `$HOME`, ntfy topic and dedup dir as the cron context); scripts that need root (`roost-net.sh`, `ram-monitor.sh`, `cloudflare-assemble.sh`) leave it unset.
