# files/ — what each deployed file is for

Everything here is deployed by `roost-apply push` from the manifest in `scripts/roost-apply.sh`, an explicit list with no globs, so a new file needs a manifest line. This file keeps the per-file facts you need before editing; most units and scripts also give their reasons in their own comments. `hooks/`, `scripts/`, `scheduled/`, `travel/`, `beeper/` and `laptop/` have their own CLAUDE.md, and `private/` has a README.

## Claude Code config

- `settings.json` — **runtime-rewritten**: change the live `~/roost/claude/settings.json`, then backport. Never blanket-push it, and compare with `jq -S` (root CLAUDE.md). Hook wiring is described in `hooks/CLAUDE.md`. JSON has no comments, so the reasons for the non-obvious keys live here:
  - `autoContinueAtUsageLimit: true` must stay on. With it off, the app opens the `/rate-limit-options` modal on every cap, and the open modal holds the session tool's auto-resume wake until someone presses Esc.
  - Telemetry, error reporting and the feedback surfaces are off (`DISABLE_TELEMETRY`, `DO_NOT_TRACK`, `DISABLE_ERROR_REPORTING`, the feedback env switches, `feedbackSurveyRate: 0`, `autoUploadSessions: false`). With telemetry off, feature flags are not fetched either, so `CLAUDE_CODE_GB_DISK_CACHE_WHEN_TELEMETRY_OFF` makes sessions read the flags cached in `.claude.json`; that is what keeps the Monitor tool. The cache never refreshes: if tools or commands appear or vanish after a Claude Code update, this is why, and Remote Control stays unavailable.
  - `CLAUDE_CODE_DISABLE_BG_SHELL_PRESSURE_REAP=1` stops sessions killing their own idle background shells on a memory-pressure event that Bun raises falsely on Linux (oven-sh/bun#42783).
  - `CLAUDE_CODE_MAX_WEB_SEARCHES_PER_SESSION=1000` (default 200): subagents draw on their parent's budget, so a research fan-out exhausts the default. Past the cap, WebSearch refuses and names the variable.
  - `CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS=0`; `CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH=3`; `CLAUDE_CODE_DISABLE_EXPLORE_INHERIT_CAP=1` (otherwise the built-in Explore agent runs on Opus under a Fable session); `ENABLE_CLAUDEAI_MCP_SERVERS=false` (no claude.ai account connectors); `promptCacheTtl` and `subagentPromptCacheTtl` set to `1h`.
  - `permissions.ask` gates the Notion MCP write tools.
- `agent-browser-config.json` → `~/.agent-browser/config.json` — sets only `idleTimeout: "15m"`: a daemon with no commands for 15 minutes closes its Chrome and exits. That is the only cleanup for a session that ends without `agent-browser close`. The value must be a quoted duration string; an integer makes agent-browser reject the whole file and fall back to its defaults. A running daemon keeps the config it started with.
- `apparmor/agent-browser-chrome` — lets agent-browser's Chrome create the user namespaces its sandbox needs under Ubuntu 24.04's restriction (reason in the profile).
- `agents/effort-*.md` → `~/roost/claude/agents/` — the `effort-{low,…,max}` subagent types: each sets an effort level and no model, so the caller passes `model` per spawn.
- `skills/` → `$CLAUDE_CONFIG_DIR/skills/`, one directory per skill, each `SKILL.md` self-describing. `antiphon` is not here: its CLI is a uv tool built from `~/roost/code/antiphon` and that repo's `install.sh` links its skills (provisioned by `private/claude-plugins.sh`); the bridge starts on demand, so there is no roost-managed service. How `roughdraft` is installed from our fork is in its SKILL.md ("When something is broken"). The `session` skill comes from the session repo's plugin, not from here.
- `_setup-env.sh` + `setup/` — one script per concern, run by `deploy.sh`. `claude-config.sh` ends by sourcing `private/claude-plugins.sh` if present, which keeps plugin specifics out of this public repo. `snapper.sh` converts the regenerable trees into nested subvolumes with a reflink copy and swap, leaving `<dir>.old` to be removed later.

## Shell

- `bashrc-append.sh` / `profile-append.sh` — stubs appended to `~/.bashrc` / `~/.profile` that source `~/.bashrc.d/$ROOST_DIR_NAME.sh`.
- `shell/bashrc.sh` → `~/.bashrc.d/roost.sh`. Running shells re-source it at their next prompt after a deploy (`tests/bashrc-reload.sh`), so every edit must be safe to source twice; only the fnm init runs once per shell. Targets on the `main` tmux session are written `=main`, an exact match: plain `main` also matches by prefix and silently lands in a grouped view such as `main-pixel` when `main` is gone. The exception is `new-session -t main`, which needs the group lookup; `=main` there would start a new group literally named `=main`. The Roughdraft review UI binds the tailnet address only when the token file `~/.config/roughdraft/token` exists (0600, generated on the box, never in the repo); without it, loopback only.
- `tmux.conf` — the focus hooks feeding `session --focus-mark` (the `#{hook_client}` gotchas are commented inline), `xterm*:hyperlinks` for the statusline's task link, and a `session-closed` hook running `lib/tmux-main-guard.sh --if-attached`, which rebuilds `main` from its group. `--if-attached` stops a teardown of the last views from resurrecting `main` and with it the whole server. `renumber-windows` applies only from the next window close, so a session that already has gaps needs one `tmux move-window -r -t '=main'`.

## Networking and services

- `Caddyfile` (envsubst template, `default_bind $TAILSCALE_IP`, imports `/etc/caddy/sites-enabled/*`) + `caddy-tailscale.conf` (drop-in: wait for Tailscale).
- `apps.caddy` → `sites-enabled/apps.caddy` — the `:8090` listener that imports `apps-enabled/*`. It also binds loopback, because `tailscale serve` accepts only loopback targets, and no app under it may send `Access-Control-Allow-*` headers (the fitness API's CSRF defence depends on cross-origin preflights failing).
- `caddy-secrets.conf` — drop-in feeding `{env.NAME}` credentials to Caddy sites. `/etc/caddy/secrets.env` is hand-provisioned (root:caddy 0640, in no repo; recreate it after a rebuild). Every variable needs a deny-all bcrypt default in the drop-in, or a missing secrets file fails the whole config load. A change needs `daemon-reload` and a Caddy **restart**, not a reload.
- `cloudflare-config.yml` — the tunnel base template, deployed to `/etc/cloudflared/config.yml.base`. `lib/cloudflare-assemble.sh` merges it with `~/roost/cloudflared/apps/*.yml` into the live `/etc/cloudflared/config.yml` (run by `roost-apply --cloudflare` and by a push of this file). Never write the template to the live path, or the assembled ingress is lost.
- `ntfy-server.yml` → `/etc/ntfy/server.yml` (`0.0.0.0:2586`, v4-only, auth required). `tailscaled-iptables.conf` pins tailscaled to the iptables backend so the travel VPN's fwmark mask has predictable bits to avoid. `sshd/50-clip-forward.conf` sets `StreamLocalBindUnlink yes` for the laptop clipboard socket. `et.cfg` binds Eternal Terminal to the Tailscale IP only.
- `dufs.service` — read-only on `127.0.0.1:5000`, served as `drop.$DOMAIN` on the Tailscale IP `:443` with the Vision wildcard cert (`caddy` is in group `xray` to read it), downloads forced to `attachment`. `setup/dufs.sh` writes that Caddy site as `sites-enabled/drop.caddy`, but the live one is `caddy-sites/tailnet-drop.caddy`, which is not in the manifest.
- `privatebin/` — config, php-fpm pool, Caddy site (loopback origin `127.0.0.1:8095`; write methods from the tunnel get 403) and the `paste.$DOMAIN` ingress template. The health check asserts the write gate.
- `glances.service`, `ram-monitor.{service,timer}`, `earlyoom.default` (restart on push; rationale inline), `btrfs-convert.sh` (rescue-mode ext4 → btrfs).
- `notion-webhook.service`, `granola-webhook.service` — receivers run from the `~/roost/code/notion-mirror` and `~/roost/code/granola-mirror` clones (unit comments cover their environment; the granola receiver refuses to start without its signing secret). `Restart=on-failure` does not pick up file changes: after editing a receiver, run `sudo systemctl restart <unit>`; to roll back, revert the file, then restart.
- `session.conf`, `session-focus-tick.*`, `roost-session-resume.service` — what feeds the `session` tool (`scripts/CLAUDE.md`).
- `cron-roost` — the base crontab. App cron goes in `/etc/cron.d/${ROOST_DIR_NAME}-apps`, private mirrors in `private/cron-mirrors`.
- `lib/_hook-env.sh` — the shared helpers for hooks and jobs (`hook_input`/`hook_json`, `ntfy_send`, `rate_limit_ok`, the `roost/<script>` log tag). Cron-context scripts set `HOOK_DROP_TO_SUDO_USER=1` before sourcing it (why is in the lib).
