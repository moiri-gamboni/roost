# files/ — what each deployed file is for

Everything here is deployed by `roost-apply push` from the manifest in `scripts/roost-apply.sh` (explicit list, no globs: a new file needs a manifest line). The root `CLAUDE.md` has the one-line map; this file holds the per-file detail that only matters when editing them. Subdirectories with their own `CLAUDE.md`: `hooks/`, `scripts/`, `scheduled/`, `travel/`, `beeper/`, `laptop/`, `private/` (README there).

## Claude Code config

- `settings.json` — **runtime-rewritten** (see root CLAUDE.md: never blanket-push, diff with `jq -S`). Carries the hook definitions (Notification + perm-mark; UserPromptSubmit usage line + turn start, plus the asyncRewake auto-resume waiter entries on UserPromptSubmit and StopFailure; Stop/StopFailure/SessionEnd/Subagent*/PostCompact lifecycle events; PostToolUse shellcheck; PreToolUse notion-write-guard + truncation-guard on Bash, fork-context-guard + redelegation-guard on Agent; a second SubagentStart entry for subagent-context; SessionStart agent-browser-session for a per-session browser; WorktreeCreate + a second SessionEnd entry for `agent-worktree` composite session worktrees), the Notion `permissions.ask` gate, the cleanup policy, the telemetry-off `env` block (`DISABLE_TELEMETRY`, `DO_NOT_TRACK`, `DISABLE_ERROR_REPORTING`, the feedback-survey and `/feedback` switches, with `feedbackSurveyRate: 0` and `autoUploadSessions: false` beside it; telemetry off also stops feature-flag fetching, so `CLAUDE_CODE_GB_DISK_CACHE_WHEN_TELEMETRY_OFF` makes sessions read the flag answers cached in `.claude.json` instead — that is what keeps the Monitor tool; the cache never refreshes, so a Claude Code update that changes flags shows up as tools or commands quietly appearing or vanishing, and Remote Control stays unavailable; `CLAUDE_CODE_DISABLE_BG_SHELL_PRESSURE_REAP` keeps a session from killing its own idle background shells — by default one is killed on the runtime's `memoryPressure` event once the session has gone 30 min without a keypress with no turn or subagent running, and on Linux Bun 1.4.x raises that event falsely shortly after every arm, so background waits died with most of RAM available: oven-sh/bun#42783, anthropics/claude-code#78674; the env block reaches running sessions on the next background command), and `autoContinueAtUsageLimit: true`, which must stay on: with it off the app auto-opens the `/rate-limit-options` modal on every cap, and an open modal parks the waiter's queued wake until a human presses Esc (verified on 2.1.241). On, no dialog opens; the waiter's wake submits a turn, which is the built-in episode's `manual_submit` disarm, so the two never double-fire. The `env` block also sets `CLAUDE_CODE_MAX_WEB_SEARCHES_PER_SESSION` to 1000, up from a default of 200 (as of 2.1.278). Subagents draw on their parent session's WebSearch budget, so a research fan-out can exhaust it even when the parent itself searched only once. Past the cap, WebSearch returns a refusal naming the variable rather than an error. A raised cap reaches a running session that is already blocked on its next WebSearch call, with no restart needed.
- `agent-browser-config.json` → `~/.agent-browser/config.json` — agent-browser's user-level defaults, read by each daemon when it starts (a running one keeps what it started with). It sets only `idleTimeout: "15m"`: a daemon with no commands for 15 minutes closes its Chrome and exits (upstream's default is an hour). That timeout is also the whole cleanup for a session that ends without `agent-browser close`, since SessionEnd is not guaranteed to fire. The value must be a quoted duration string: an integer makes agent-browser reject the whole file with a warning and fall back to its defaults. An idle shutdown drops open tabs and cookies; the next command starts a fresh browser. `setup/dev-tools.sh` installs it on a fresh box.
- `_setup-env.sh` — sourced by every `setup/` script; reads the server copy of `.env`, exports `USERNAME`, `HOME_DIR`, etc., provides `as_user()`.
- `setup/` — one script per concern, run by `deploy.sh` via `remote_script()`. `claude-config.sh` ends with a generic source-if-present hook for `private/claude-plugins.sh`, so plugin specifics stay out of the public repo. `dev-tools.sh` adds the user to `docker` and symlinks fnm's default `node`/`npx` into `~/bin`. `snapper.sh` creates the root config and converts the regenerable trees into nested subvolumes (list in the script; conversion is a reflink copy + swap, leaving `<dir>.old` for a later removal). `attention-queue.sh` creates the `beeper` user and the four nested subvolumes that hold decrypted message text (created empty, an existing plain directory is refused), installs Beeper Server pinned and sha512-checked, and enables the `beeper/` units (`files/beeper/CLAUDE.md`).
- `skills/` — deployed to `$CLAUDE_CONFIG_DIR/skills/`: `antiphon` (delegate to OpenAI Codex: Codex threads as live peers of the session — start/steer/message/approve — via the `antiphon` CLI; the CLI is a uv tool at `~/.local/bin/antiphon`, from `~/roost/code/antiphon`, and the bridge lazy-starts, so there is no roost-managed service), `html2markdown`, `havelock-api`, `humanizer`, `pastebin` (PrivateBin via pbincli), `roughdraft` (put a Markdown file in front of the user for review; the fork/install half stays in the global CLAUDE.md), `session` (the session CLI), `zotero` (batch-manipulate a Zotero library; written for the guest device, works headless here via the web API).

## Shell

- `bashrc-append.sh` / `profile-append.sh` — stubs appended to `~/.bashrc` / `~/.profile` that source `~/.bashrc.d/$ROOST_DIR_NAME.sh` (interactive and non-interactive shells).
- `shell/bashrc.sh` → `~/.bashrc.d/roost.sh` — PATH, tmux, the `agent`/`agents`/`attach` helpers. Idempotent: only the fnm init is once-per-shell, so a plain re-`source` applies a new deploy, and a `PROMPT_COMMAND` hook does exactly that at the next prompt of every running interactive shell once the deployed file's mtime changes (`tests/bashrc-reload.sh`). Targets on the `main` session are written `=main`, the exact-match form: a plain `-t main` also resolves by fnmatch and then by *prefix*, so with the session killed and one grouped view alive it silently lands in `main-pixel` and the breakage stays invisible until a second view makes the prefix ambiguous. The one deliberate exception is `new-session -t main`: that flag also accepts a session *group* name, which is what lets the group rejoin work at all, and `=main` there would quietly start a second group literally named `=main`. Exports the Roughdraft env: `ROUGHDRAFT_BIND_HOST` (loopback + `tailscale ip -4`, so the review UI on `:7373` is reachable from the tailnet), `ROUGHDRAFT_TOKEN` (from `~/.config/roughdraft/token`, `0600`, generated on the box, never in the repo: Roughdraft refuses a non-loopback bind without one because its remote-document endpoints rewrite files on disk; no token file = loopback-only, the right degraded state for a fresh server) and `ROUGHDRAFT_NO_OPEN=1`.
- `tmux.conf` — the client-focus-in/out/detached and session-window-changed hooks feed `session --focus-mark` (attended time for `session time`). The two tmux-3.4 gotchas (`#{hook_client}` is the only correct client reference in a per-client hook; there is no `client_focused` format, test with `#{m:*focused*,#{client_flags}}`) are commented inline at the hook lines. A `session-closed` hook runs `lib/tmux-main-guard.sh --if-attached`, which rebuilds `main` from its session group when something kills it; `--if-attached` is what stops a teardown of the last views from resurrecting the session and with it the whole server. Status bar: the current window's `#{pane_title}` (the Claude session name) alone, plus `session #{window_index}/#{session_windows}` and the clock — the other windows are not listed, `agents` is how you switch. `renumber-windows on` is what keeps that X/Y honest, and only applies from the next window close, so a session with existing gaps needs one `tmux move-window -r -t '=main'`.

## Networking and services

- `Caddyfile` (envsubst template; `default_bind $TAILSCALE_IP`; imports `/etc/caddy/sites-enabled/*`) + `caddy-tailscale.conf` (systemd drop-in: wait for Tailscale before starting).
- `caddy-secrets.conf` — systemd drop-in giving Caddy the credentials its public-route sites reference as `{env.NAME}`, so no password or hash is committed to this public repo. `EnvironmentFile=-/etc/caddy/secrets.env` is **hand-provisioned** (root:caddy 0640, in no repo; recreate it after a rebuild). Every variable also gets a deny-all `Environment=` default here — a well-formed bcrypt string with no preimage — because `EnvironmentFile=` overrides `Environment=` when the file exists, and because Caddy refuses to provision an empty or non-bcrypt `basic_auth` password: without the default, a missing secrets file would fail the whole config load and take every other site on the box down. A change to the file or the drop-in needs a Caddy **restart**, not a reload (reload re-reads the Caddyfile inside the running process and leaves its environment alone).
- `cloudflare-config.yml` — tunnel base template, deployed to `/etc/cloudflared/config.yml.base`. `lib/cloudflare-assemble.sh` reads its tunnel header and merges `~/roost/cloudflared/apps/*.yml` into the live `/etc/cloudflared/config.yml` (run by `roost-apply push files/cloudflare-config.yml`, `roost-apply --cloudflare`, or standalone). Never write the template to the live path: it clobbers the assembled ingress.
- `ntfy-server.yml` → `/etc/ntfy/server.yml` — listens `0.0.0.0:2586` (v4-only pin), auth required.
- `tailscaled-iptables.conf` — drop-in pinning `tailscaled` to the iptables backend so the travel VPN's masked fwmark has predictable Tailscale mark bits to work around.
- `sshd/50-clip-forward.conf` — `StreamLocalBindUnlink yes` for the laptop clipboard-forward socket.
- `dufs.service` — read-only (`--allow-upload`/`--allow-delete` off) on `127.0.0.1:5000`; Caddy site `sites-enabled/drop.caddy` on the Tailscale IP `:443` with the `*.$DOMAIN` Vision wildcard cert (`caddy` in group `xray`; `vision-cert-renew.service` reloads Caddy after renewal), rewriting `Content-Disposition: inline` → `attachment` so HTML/JS downloads instead of rendering.
- `privatebin/` — `conf.php` (markdown default formatter, discussion off, CF-aware rate limiting; → `/etc/privatebin/`), `php-fpm-pool.conf` (dedicated `privatebin` user; socket consumed by Caddy), `privatebin.caddy` (loopback origin `127.0.0.1:8095` + the public write gate: tunnel-tagged (`CF-Connecting-IP` present) write methods → 403), `privatebin-cloudflare.yml.tmpl` (ingress for `paste.$DOMAIN`; `deploy.sh` ensures the proxied CNAME). App at `/var/www/privatebin` (root-owned; same-major updates via the daily auto-update), pastes under `/var/lib/privatebin/data` (owner `privatebin`). The health check asserts the write gate every 5 minutes.
- `glances.service`, `ram-monitor.service`/`.timer` (30s), `earlyoom.default` (`/etc/default/earlyoom`, restart on push), `btrfs-convert.sh` (rescue-mode ext4 → btrfs with `@rootfs`).
- `notion-webhook.service` — the Notion webhook receiver (`~/roost/code/notion-mirror/webhook_receiver.py`; `Environment=CLAUDE_CONFIG_DIR` names the roost config dir, where the receiver reads the Notion token on the first comment event).
- `granola-webhook.service` — the Granola webhook receiver (`~/roost/code/granola-mirror/webhook_receiver.py`, `127.0.0.1:8097`, routed as the `^/granola` path on the hooks hostname via the `granola-hooks.yml` tunnel fragment). Primary trigger for the granola-mirror pipeline: a Standard-Webhooks-verified `note.generated`/`note.edited`/`note.access_granted` event kicks the clone's `refresh.sh --commit`, debounced, under the same flock as the fallback cron. Refuses to start without the signing secret at `~/.config/granola/webhook-secret` (written once at endpoint registration; see the receiver's docstring).
- Both webhook units: `Restart=on-failure` does not reload on file change; edit → `sudo systemctl restart <unit>`; rollback = revert the file, then restart.
- `cron-roost` — the base crontab (health checks, scheduled jobs, auto-update); app cron goes in `/etc/cron.d/${ROOST_DIR_NAME}-apps`, private mirrors in `private/cron-mirrors`.
- `lib/_hook-env.sh` — `hook_input()`/`hook_json()`, `ntfy_send()` (journald fallback), `rate_limit_ok()`, `logger -t "$_HOOK_TAG"` (`roost/<script>`); `set -uo pipefail` without `-e`. Cron-user scripts set `HOOK_DROP_TO_SUDO_USER=1` before sourcing so an ad-hoc `sudo` run re-execs as `$SUDO_USER` (same `$HOME`, ntfy topic and dedup dir as the cron context); scripts that need root (`roost-net.sh`, `ram-monitor.sh`, `cloudflare-assemble.sh`) leave it unset.
