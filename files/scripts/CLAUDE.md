# scripts/ — user CLIs

Deployed to `~/roost/claude/scripts/` and symlinked into `~/bin`. `roost-apply.sh` (config deployment; usage in the root CLAUDE.md) and `roost-net.sh` (travel VPN; `files/travel/CLAUDE.md`) are documented elsewhere. This file is about `session.sh`, whose header already lists every mode and the guard config; what follows is the cross-file mechanism.

## Data flow

The statusline (`hooks/statusline.sh`) is the only writer of the usage data under `~/roost/claude/usage/`: `last-status.<email>.json` (per-login rate-limit cache), `session-log.tsv` (21-column per-render samples: cost, rate-limit %s, durations, cumulative tokens, context composition, lines added/removed, model, prompt_id, account), the pane→session map for focus tracking. The hooks write `turn-log.tsv` (start/end/lifecycle events) and tmux's focus hooks write `focus-log.tsv`. Live logs keep 8 days; a daily sweep moves older lines to `usage/archive/<same-name>.tsv`, append-only, so time-tracking history is permanent while the hot files stay fast.

`session` reads those: per-session $ burn is counted from the cost samples; est % of a limit = the global %-movement observed while sampling was live, split by tracked-$ share (pre-coverage burn stays unattributed; headless `claude -p` and off-box usage are invisible and inflate shares). Everything limit-related is keyed by login (the email in the invoking `$CLAUDE_CONFIG_DIR/.claude.json`): cache read and attribution filter (sample-log column 21) alike, so concurrent accounts never mix. `session time` stays account-agnostic: active = Σ closed start→end turn spans (idle excluded, `claude -p` covered; `cost.total_duration_ms` is session wall clock ticking through idle, verified, so it cannot give this); attended = the tmux focus log; `time --all` adds a `you` row, the union of attend spans, and there is deliberately no per-session sum (parallel sessions each count in full).

Countdowns round rather than floor and drop to h+m below a day (flooring hid up to 59m: 58m of weekly headroom printed `0d00h`). A snapshot whose `resets_at` has passed shows `~0%`: the weekly is projected forward on its fixed 7-day cadence, the 5h is not projectable (usage-anchored: it opens on the first request after an idle gap) and prints `?`; `--guard` won't pause on a stale window.

`session peers` reads Claude Code's presence registry `$CLAUDE_CONFIG_DIR/sessions/<pid>.json`: cross-session address (ListAgents name = SendMessage `to:`) ↔ session id + title; REACH `no` = registered but invisible to ListAgents until that session restarts. `session name`/`id` look up id↔title across sessions (8-day snapshots first, transcript store as the slow fallback; title→id greps GBs with a stderr warning).

## `session account` — multi-login, one config dir

Several subscription logins out of ONE config dir, swapped in place, so transcripts, memory, settings, MCP servers and history stay shared and `--resume` keeps working. The live login is `.credentials.json`'s `claudeAiOauth` + `.claude.json`'s `oauthAccount`; the vault `claude/accounts/<email>.json` (0600, dir 0700) holds every login seen. `list` shows each login's rate-limit headroom and reset countdowns (the question you switch on; a non-live login's snapshot ages from the switch). `use <substring>` swaps only `claudeAiOauth`: `mcpOAuth` (Granola, DoneThat) is not account-scoped and must survive. `save`/`rm` are explicit. `/login` is not destructive: the statusline autosaves the live login whenever `.credentials.json`'s mtime moves, and vault entries are never overwritten in place (the previous copy rotates into `accounts/.history/`).

A switch reaches running sessions on their next request, no restart, no re-auth. Mechanism (read out of the 2.1.220 bundle): the token is memoized in `ms.cache`, but building an API client awaits `Dy()` → `HHg()`, which `stat`s `.credentials.json` and calls `EW()` to clear that memo when the mtime moved; on Linux the plaintext backend's `read()` is an uncached `readFileSync` (the TTL cache belongs to the macOS keychain path). Measured 2026-07-31 on a controlled session: 5h 36%/wk 66% before, and the first request after the swap reported the other account's 5h 4%/wk 100%. Two consequences: the switch is box-wide (every `claude` shares the config dir), and between requests the statusline merely repeats the last API response, so displayed %s catch up one turn later; misreading one of those stale repeats is what first made this look like it had not switched.

`--wait` (any variant) also exits within ~1s of a login switch, via an inotify watch on the config dir (15s polling without inotifywait): the wait was armed against the old login's window, so the switch is the wake-up.
