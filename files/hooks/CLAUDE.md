# hooks/ — Claude Code event hooks

Deployed to `$CLAUDE_CONFIG_DIR/hooks/`, wired in `files/settings.json`. Each script's header carries its own rationale; this file is the cross-hook picture. The usage-limit hooks are subcommands of `scripts/session.sh` (its header documents `--hook`, `--rewake-waiter`, `--turn-end` and the turn-log format in full).

| Event | Script | Mechanism |
|---|---|---|
| Notification | `notify.sh` | ntfy push via `_hook-env.sh`, rate-limited, priority by notification type |
| UserPromptSubmit (`timeout: 2`) | `session.sh --hook` | Warn-gated: silent below `USAGE_WARN_PCT` (90). At/above it, injects a self-identifying one-line `Claude usage limits · date/time · 5h % · weekly %` (+ reset countdowns, phrased `resets to 0% in …` so it can't read as a deadline) through `hookSpecificOutput.additionalContext`, `suppressOutput` keeping it out of the transcript. The leading tag is needed because `additionalContext` reaches the model as a bare string. Appends ONE ⚠ advisory whatever the window: keep working, fan-out included, the waiter is armed (falls back to instructing a background `session --wait` if settings.json lacks the asyncRewake entry). After a warned reset passes or the login switches to an unwarned account, the next turn gets a one-line refresh notice once (per-session state `usage/sessions/<sid>.warn` = reset ts + login). Ends with `this session ≈X%/5h ≈Y%/wk`. Side effect every turn: the `s` row in `usage/turn-log.tsv`. Always exits 0 |
| UserPromptSubmit + StopFailure (second entries, `asyncRewake: true`, timeout 700000) | `session.sh --rewake-waiter` | asyncRewake backgrounds the hook and treats exit 2 as "wake the model with stderr as a system reminder" through the task-notification channel, so it wakes an idle session (verified end-to-end on 2.1.233 for UserPromptSubmit; the field is schema-generic across events). UserPromptSubmit: below the threshold every spawn exits 0; above it the first spawn per session becomes the waiter (pidfile `usage/sessions/<sid>.rewaiter`, newest wins). StopFailure: arms only when the turn died on a usage cap (error ~ `rate_limit`), regardless of threshold: the one path covering a cap arriving mid-turn. Sleeps to the earliest warned reset (≤300s chunks) and exits 2 at the reset or within ~1s of a login switch (inotify on the config dir; 15s polling without inotifywait). Exits 0 without waiting under a `claude -p` parent, where the harness runs the hook synchronously. `rewakeMessage`/`rewakeSummary` in settings.json set the reminder prefix and the terminal line |
| Stop · StopFailure · SessionEnd · SubagentStart/Stop · PostCompact · Notification(permission_prompt) | `session.sh --turn-end` / `--turn-fail` / `--session-end` / `--subagent-start` / `--subagent-end` / `--compact-mark` / `--perm-mark` | Lifecycle rows (`e f x a z c p`; `s` from the hook above) for `session time`: turn spans + prompt_id, API-failure ends (detail = error type), terminations, subagent spans paired by agent_id, compactions, permission-wait markers. All exit 0: several of these events treat exit 2 as "block" |
| PostToolUse (Edit\|Write) | `shellcheck-edit.sh` | shellchecks an edited `*.sh`, returns findings as `additionalContext` (warning severity, 40-line cap, silent on clean files) |
| PreToolUse (Bash) | `notion-write-guard.sh` | Denies a write verb (`-X`/`--request`/`method=`/a client `.post(`-class call) aimed at `api.notion.com` in the raw command string; `apart-tools/tasksync/` and `apart-tools/notion-mirror/` invocations are allow-listed (the clone root alone is deliberately not enough). Keys on the host, so SDK calls never match and the MCP tools stay gated by `permissions.ask`. Never logs the command (they carry tokens). Matcher table: `notion-write-guard.test.sh` (25 cases, not deployed). Does not source `_hook-env.sh`: it fires on every Bash call and cannot afford the `tailscale ip` subprocess |
| PreCompact | `reflect.sh` + `reflect.md` | Disabled (the memory/reflection system is not in use); just cats a prompt file |
| statusline | `statusline.sh` | TUI status line. Also the writer of everything the `session` CLI reads: the per-login rate-limit cache, the per-session sample log, the pane→session map, and the autosave of the live login into the account vault. Mechanism in its header |
