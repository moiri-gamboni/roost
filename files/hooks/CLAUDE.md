# hooks/ — Claude Code event hooks

Deployed to `$CLAUDE_CONFIG_DIR/hooks/`, wired in `files/settings.json`. Each script's header carries its own rationale; this file is the cross-hook picture. The usage-limit hooks and the statusline are the `session` tool's (`~/roost/code/session`; wired by its `install.sh`, documented in its README) — the rows below stay as the cross-hook picture of what runs on this box.

| Event | Script | Mechanism |
|---|---|---|
| Notification | `notify.sh` | ntfy push via `_hook-env.sh`, rate-limited, priority by notification type |
| UserPromptSubmit (`timeout: 2`) | `session --hook` | Warn-gated: silent below `USAGE_WARN_PCT` (90). At/above it, injects a self-identifying one-line `Claude usage limits · date/time · 5h % · weekly %` (+ reset countdowns, phrased `resets to 0% in …` so it can't read as a deadline) through `hookSpecificOutput.additionalContext`, `suppressOutput` keeping it out of the transcript. The leading tag is needed because `additionalContext` reaches the model as a bare string. Appends ONE ⚠ advisory whatever the window: keep working, fan-out included, the waiter is armed (falls back to instructing a background `session --wait` if settings.json lacks the asyncRewake entry). After a warned reset passes or the login switches to an unwarned account, the next turn gets a one-line refresh notice once (per-session state `usage/sessions/<sid>.warn` = reset ts + login). Ends with `this session ≈X%/5h ≈Y%/wk`. Side effect every turn: the `s` row in `usage/turn-log.tsv`. Always exits 0 |
| UserPromptSubmit + StopFailure (second entries, `asyncRewake: true`, timeout 700000) | `session --rewake-waiter` | asyncRewake backgrounds the hook and treats exit 2 as "wake the model with stderr as a system reminder" through the task-notification channel, so it wakes an idle session (verified end-to-end on 2.1.233 for UserPromptSubmit; the field is schema-generic across events). UserPromptSubmit: below the threshold every spawn exits 0; above it the first spawn per session becomes the waiter (pidfile `usage/sessions/<sid>.rewaiter`, newest wins). StopFailure: arms only when the turn died on a usage cap (error ~ `rate_limit`), regardless of threshold: the one path covering a cap arriving mid-turn. Sleeps to the earliest warned reset (≤300s chunks) and exits 2 at the reset or within ~1s of a login switch (inotify on the config dir; 15s polling without inotifywait). Exits 0 without waiting under a `claude -p` parent, where the harness runs the hook synchronously. `rewakeMessage`/`rewakeSummary` in settings.json set the reminder prefix and the terminal line |
| Stop · StopFailure · SessionEnd · SubagentStart/Stop · PostCompact · Notification(permission_prompt) | `session --turn-end` / `--turn-fail` / `--session-end` / `--subagent-start` / `--subagent-end` / `--compact-mark` / `--perm-mark` | Lifecycle rows (`e f x a z c p`; `s` from the hook above) for `session time`: turn spans + prompt_id, API-failure ends (detail = error type), terminations, subagent spans paired by agent_id, compactions, permission-wait markers. All exit 0: several of these events treat exit 2 as "block" |
| PostToolUse (Edit\|Write) | `shellcheck-edit.sh` | shellchecks an edited `*.sh`, returns findings as `additionalContext` (warning severity, 40-line cap, silent on clean files) |
| PreToolUse (Bash) | `notion-write-guard.sh` | Asks before a write verb (`-X`/`--request`/`method=`/a client `.post(`-class call) aimed at `api.notion.com` in the raw command string — `permissionDecision: "ask"`, so the user sees what is about to be written and can approve it as is (the prompt text is theirs; the sanctioned path reaches the model as `additionalContext`; where nothing can prompt, ask is a deny); invocations through a `tasksync/` or `notion-mirror/` directory are allow-listed wherever the clone sits — absolute, worktree or relative path — while a bare mention of the directory (`cd notion-mirror && …`) is deliberately not enough. Notion's POST-shaped **reads** are exempt, paired per statement: the command is cut into segments at newlines and `;`/`|`/`&&`/`||`, and every segment carrying a write verb must name one `api.notion.com/v1/…` path per write call, each ending in `/query` (data source or database) or being `/v1/search` — a paginated dump of the workspace is all POST and all read, and a schema GET on its own line beside the row query is no reason to ask. A write segment naming no path (a call split across lines, a URL in a variable) gathers paths from up to three neighbouring segments on each side — only a literal standing as a value (quoted, after `=`/`(`, or first on its line), never a URL inside a longer string such as a progress print — stopping at any other HTTP call; nothing gathered, a gathered write path, or more calls than paths on one segment, and the prompt stands. Keys on the host, so SDK calls never match and the MCP tools stay gated by `permissions.ask`. Never logs the command (they carry tokens). Matcher table: `notion-write-guard.test.sh` (51 cases, not deployed). Does not source `_hook-env.sh`: it fires on every Bash call and cannot afford the `tailscale ip` subprocess |
| PreToolUse (Bash) — **unwired** | `truncation-guard.sh` | Disabled: deployed, but no `settings.json` entry runs it; re-enable by adding it back beside `notion-write-guard.sh` in the Bash `PreToolUse` entry. When wired, it denies `head`/`tail` in command position with a line count under 100 — `-n N`, `-nN`, `-N`, `--lines=N`, sign ignored — or with no count at all (the default is 10). `-c`/`--bytes`, `--help`, and a `tail -f`/`-F`/`--follow` without a count pass; `-n 100` and above pass. Matches the command with heredoc bodies and quoted spans stripped (that order; `$`-bearing double-quoted spans are kept so `"$(… \| head -5)"` is seen), so `bash -c '…'` bodies and scripts on disk are out of reach by design. **sed**, whose script is the quoted span, gets its own pass on the heredoc-stripped command with quotes intact (one gawk, only when the word occurs; a quoted string is one token, so a mention is never a command): `sed -n` denies when its numeric `p` ranges (`A,Bp`, `Np`, `$p`, `A,+Kp`, `N,$p` with N < 100 — the `tail -n +N` rule) sum to under 100 lines, `sed Nq` with N < 100 denies with or without `-n` and caps whatever the ranges say; `-i`, `-f`, a script carrying a shell `$`, regex-addressed or unaddressed `p`, `1,$p` and negated addresses pass. **cut** `-c`/`-b`/`--characters`/`--bytes` denies at any width (`-d`/`-f` field selection passes; the flag cluster is cut's argument-less letters only, so `-dc` is a delimiter). **grep-family** (grep/egrep/fgrep/rg/ugrep/ug) denies when a context window under 100 lines (`-A`+`-B`+2×`-C`, long forms included) targets a file that exists — a windowed read of a known file, `head -N` anchored at a match — with the target checked against the payload `cwd` and every `cd` target in the command; no context flags, `-r`, a 100+ window, piped/pattern-only greps and missing files pass (a quoted pattern is stripped with its quotes, so only real file arguments land in the check). Deny message names the file, the rule and the alternatives (never the off switch). A `tasks` (tasksync) verb piped into head/tail denies at ANY count — that CLI's output is read whole (the cut lines are the consistency gate's findings and the beat's notices); the match spans a pipeline (`2>&1` and intermediate filters included) and stops at `;`/`&&`/`||`. Matcher table: `truncation-guard.test.sh` (150 cases, not deployed). Does not source `_hook-env.sh`: fires on every Bash call |
| PreToolUse (Write\|Edit) | `roughdraft-write-guard.sh` | Snapshots the pre-write bytes of any CriticMarkup-bearing `.md` before an agent overwrites it. Snapshot-only: always `exit 0`, never any stdout — `permissionDecision: "ask"` is a hard deny wherever no prompt surface exists (background subagents, `claude -p`, `dontAsk`), most of this box's traffic, and friction is what got `no-truncation.sh` reverted. Bail ladder, cheapest first: no stdin → one `jq` for `tool_name`+`file_path` → `Write`/`Edit` only → `*.md` → not inside a `.roughdraft-history/` segment (case-insensitive, matching the Roughdraft server) → readable regular file → fixed-string marker grep (`{#` anchors alone don't count). Snapshots land in `<dir>/.roughdraft-history/v1/<stem>/<UTC ts>--p<pid>--hook.md` — a frozen cross-repo format shared with the Roughdraft repo's `checkpoint-store.ts` and specified in its `docs/spec/history-sidecar.md`; recover with `roughdraft history <file>` or from the sidecar directly. Content-only dedup vs the newest entry; 90s debounce against the hook's own `--hook` snapshots ONLY (a fresh `--save`/`--review` from another writer never suppresses a capture — that would drop everything the reviewer typed after the save); prune to 50 oldest-first pinning the newest `--review` entry; only names matching the id grammar count as snapshots (a planted `zzz.md` is never the dedup baseline, never counted, never evicted); `.gitignore` (`*`) written into the sidecar; `[ -L ]` refusal at all three dir levels; prune never uses `ls \| xargs`. Every refusal that leaves a document unprotected logs a reason (path only, never content). Does not source `_hook-env.sh`: it fires on every Write and Edit. Tests: `roughdraft-write-guard.test.sh` (not deployed; run it for the case list). Liveness: the `health-check-apps.sh` probe checks three deaths — still works (one fixture per marker, executed through its shebang, failing on no snapshot or any stdout), still wired (a `PreToolUse` entry naming it whose matcher covers both `Write` and `Edit`), and not disappeared since it last worked (`state/roughdraft-hook-deployed` marker; before it exists the probe is silent). Rollout: hook config is read at session start — deploys and removals reach only new sessions. The settings entry is edit-live-then-backport; never blanket `roost-apply push files/settings.json` |
| PreToolUse (Agent) | `fork-context-guard.sh` | Turns a `subagent_type: "fork"` into a permission prompt once the session's context passes 500k tokens. The figure is the newest assistant row's usage in the payload's `transcript_path` (input + cache_read + cache_creation, the request's context, per-session by construction — the `session` overview's context line is per-login), read from the end: `sed '$a\'` supplies the newline a torn last line lacks (otherwise tac glues it to the row before), then `tac`, `grep -m 40`, `fromjson?`; 26 ms on a 1.6 MB transcript, 0.3 s on 78 MB. The 40 is a correctness bound too: a usage row behind 40 usage-less assistant rows is invisible and the guard falls open (real transcripts carry usage on every assistant row; the boundary is pinned in the tests). A readable transcript that yields no usable row is the one allow that logs (`journalctl -t roost/fork-context-guard`), since it is what a transcript-format change would look like. Returns `permissionDecision: "ask"` with the figure in the prompt text (shown to the user, not Claude) and the same figure as `additionalContext` for the model (per the hooks reference, not yet observed). A hook's ask forces the prompt even in auto mode; where nothing can prompt (`claude -p`, a background subagent with no surface) ask is a deny, which is the cap holding. Non-forks and any parse problem pass; never names the off switch. Matcher table: `fork-context-guard.test.sh` (not deployed). Does not source `_hook-env.sh`. Hook config is read at session start: reaches new sessions only |
| PreToolUse (Agent) | `redelegation-guard.sh` | Denies a subagent's hand-off of its own brief. Fires only inside a subagent (`agent_id` in the payload; the main thread is never touched). `transcript_path` is the parent session's transcript even inside a subagent, so the subagent's own rows are read from `<session-dir>/subagents/agent-<agent_id>.jsonl`; the brief is that file's first user row — for a fork, the directive after the last user row that *starts with* `<fork-boilerplate>` (a row merely mentioning the tag, such as an assistant quoting the global CLAUDE.md, is not the directive), and only rows from there on are the fork's own, its transcript opening with the parent's whole history. Coverage = the share of the brief's vocabulary (ASCII tokens of 4+ chars, lowercased, `LC_ALL=C`) present in the child's description + prompt; under 80% the hook exits at once, no waiting. At or above it, the hook polls up to 3 s for the assistant row carrying its own `tool_use_id` (tools run as the model streams them, so that row is usually not on disk when the hook fires; parallel siblings land with it about 0.5 s later, and the hooks for parallel calls run concurrently), settles 0.2 s and re-reads so a poll falling between two rows of one message cannot make a fan-out look like a lone call, then denies iff that row is the subagent's first spawn message and holds exactly one Agent call. 2+ legs in one message, a spawn after an earlier one (a coordinator retrying a failed leg), a row that never appears, a missing transcript or brief, or any parse problem all allow; the unseen-row and denied cases log to `journalctl -t roost/redelegation-guard`. The deny reason (what the model reads; `additionalContext` is dropped on deny) names the coverage figure, the agent type and the depth from the sidecar `meta.json`, and says what to do instead. Calibrated on the 14 days before it shipped (162 spawning subagents): every hand-off scored 0.81–0.99, every legitimate single first spawn 0.76 or under, and 12 of the 35 hand-offs had retried after the child failed. Matcher table: `redelegation-guard.test.sh` (not deployed). Does not source `_hook-env.sh`. Hook config is read at session start: reaches new sessions only |
| SubagentStart | `subagent-context.sh` | Injects one paragraph into every subagent's conversation before its first model call (`hookSpecificOutput.additionalContext`, verified on 2.1.278 with a marker string): it is a subagent of the named type, the brief in its first message is its own to execute, spawning is for splitting the brief into parallel legs or for a small part of it, never for handing the brief itself to a single child, and the global CLAUDE.md's "delegate down by default" addresses the session that briefed it. Type only: the sidecar `meta.json` (with `spawnDepth`) is written after this hook returns. Always exits 0 |
| PreToolUse (every tool) · PostToolUse (Bash\|Edit\|Write\|MultiEdit\|NotebookEdit) · UserPromptSubmit | `conflict-watch-hook.sh` | The session side of the conflict watch (`scripts/conflict-watch.py`, whose docstring and `files/scripts/CLAUDE.md` carry the daemon side). It **warns and never prompts**: the user decided against permission prompts ("I thought we decided to have the hook just send a warning, not a permission prompt"), so every stop is a `deny` whose reason is the warning, given once per session, unit and hold (`acks/<sid>`, keyed by the hold's `since`, so a release and re-hold or a new holder re-arms it; one acknowledgement covers Edit, Bash and git alike), and the retry passes. Reads `/run/conflict-watch/holds.tsv` (first line `#daemon <pid>`; no file or a dead pid → exit 0 at once: fail silent). Every event hands over the session's inbox (`inbox/<sid>`, taken by `mv` so a daemon append in flight lands in a new file) as `additionalContext` (on a deny, appended to the reason, which is all the model sees). Warned about, when another open session holds the unit: an Edit/Write/MultiEdit/NotebookEdit path inside it; a Bash command naming it — absolute, `~/`, or relative to the payload `cwd` and each `cd` target (`..` resolved), a `cd` into it, or any path-like argument while the cwd is inside it (variables, globs and scripts are left to the daemon; a command that is `conflict-watch …` itself is exempt); a repo-wide git command, through `conflict-watch hook-git`, when it would change files that session wrote in the repo the command runs in: files of a nested repo never count (their nearest `.git` is not the command's repo), and the command's affected set is intersected where git can say it cheaply — `add -A`/`commit -a`/`stash`/`reset --hard`/`clean -f`: the uncommitted files; `checkout -- <paths>`/`restore <paths>`: those paths' uncommitted files; `merge`/`rebase`/`pull`: `git diff --name-only HEAD...<ref>` (pull: the upstream as fetched so far); `checkout`/`switch <branch>`: `git diff --name-only HEAD <branch>`; an unknown ref or an unparsable form counts every such file. The warning names the holder in double quotes with busy/idle (registry), the age of its last write and its address — `SendMessage to: "<name>", session <8-char id>`: the registry `name` is what ListAgents prints and SendMessage's `to:` takes (ListAgents' ` [ref]` suffix is only needed when two sessions share a name, which the app renames away), the id is `session peers`' SESSION column, and the warning points there — plus the options: ask the user in the conversation whether to SendMessage the holder, or for a repo unit `agent-worktree isolate <repo>`. `grants/<sid>` (`conflict-watch allow`, both ways) count as acknowledged too. The holder's own helper sessions (a `claude -p` whose ancestor is the holder's pid) are never strangers. Speed: no subprocess on the common path — the payload's leading fields (session_id … tool_name, all before `tool_input`) come from a bounded `read -N 4096`, since `read` on a pipe takes a syscall per byte and an unbounded read of a multi-MB PostToolUse payload takes seconds; liveness and ancestry are checked only for units the call touches. Measured 7.7 ms per call with nothing to do and 10–12 ms for Bash/Edit with units held elsewhere, against 5.4 ms for a bare `bash -c :` on the same loaded box; a repo-wide git command adds `python3 -S hook-git`, ~105 ms of start-up plus 2–26 ms of git. Matcher table + latency: `conflict-watch-hook.test.sh` (not deployed). Hook config is read at session start: reaches new sessions only |
| SessionStart | `agent-browser-session.sh` | Appends `export AGENT_BROWSER_SESSION=<session_id>` to the file at `$CLAUDE_ENV_FILE`, which Claude Code runs as a preamble before every Bash command of the session and its subagents (verified on 2.1.278: a headless session and the haiku subagent it spawned both saw the session's id) and re-applies on `--resume` and `/clear` (CHANGELOG 2.1.136; upstream issues before that describe the export going stale). agent-browser keys its daemon and Chrome on that name (default `default`, shared by everyone), so this is what keeps sessions off each other's tabs. SessionStart fires again on `/clear`, resume and compaction against the same file, so the append is guarded by an exact-line grep. The id is checked against agent-browser's name grammar (`[A-Za-z0-9_-]`) and the hook exits 0 whatever happens; without `CLAUDE_ENV_FILE` it leaves the default. Hook config is read at session start: reaches new sessions only |
| PreCompact | `reflect.sh` + `reflect.md` | Disabled (the memory/reflection system is not in use); just cats a prompt file |
| statusline | the session clone's `statusline.sh` | TUI status line: model and effort, context size, the 5h/weekly windows, and the tasksync task the session is on — folder under the cwd, else tasksync's `tasks/.sync/session-task.json` — anchored on a link to its Notion row (clickable under tmux only because `files/tmux.conf` declares `xterm*:hyperlinks`). Also the writer of everything the `session` CLI reads: the per-login rate-limit cache, the per-session sample log, the pane→session map, and the autosave of the live login into the account vault. Mechanism in its header. Cache-attribution cases (account switch, duplicate-session flap): `tests/statusline.test.sh` in the session repo |
