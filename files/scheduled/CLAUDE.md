# scheduled/ — cron and timer jobs

Deployed to `~/roost/claude/scheduled/`. Schedules live in `files/cron-roost` unless noted, each with a comment giving its reason. Jobs source `lib/_hook-env.sh`, log to journald as `roost/<script>` and notify through ntfy. Each script's header and inline comments carry its policy and thresholds, so read them before changing one.

- `health-check.sh`, every 5 min — services (Caddy, ntfy, Tailscale, cloudflared, earlyoom) and every earlyoom kill since the last run; disk, alerting on a 3-point climb above 80% and always above 90%; btrfs **unallocated** space on `/` and `/mnt/roost-data`, which is the read-only-flip risk that `df` misses. Below 5 GiB unallocated it runs `btrfs-balance.sh` itself, then prunes the oldest timeline snapshots and balances again. It also checks that swap is active, runs the tasksync dead-man, and watches memory headroom and PSI stall and a pending reboot. Hard failures bundle into one `Service health alert`, re-sent when the failure set changes or else hourly, so a failure line must not carry a value that changes between runs of the same fault (an age, a count, an exit code): those go in the journal line only, and only the disk line carries its level, on purpose. It then sources `health-check-apps.sh` (deployed from `files/travel/travel-health.sh`, which is where app checks go) and `health-check-apps-private.sh` if present, which sources the attention queue's dead-man `health-check-attention-queue.sh` (its checks are in its header; tested by `files/private/tests/attention-queue-health.sh`).
- `auto-update.sh`, daily 2:50 — starts then so it ends before snapper's 3:00 snapshot, which would otherwise pin what the cleanup removes. Updates each tool in its sections plus OS packages, with a 7-day release cooldown and a block on major versions. It sends an ntfy only when something updated, failed or has a major version waiting. Global npm CLIs are installed with `--prefix "$HOME/.local"`, since the Node LTS bump strands a plain `npm i -g`. Xray is deliberately left out (header). It ends by running `disk-cleanup.sh`.
- `disk-cleanup.sh` — reclaims regenerable artifacts (list in the header); `--dry-run` previews. A Node version stays if it is fnm's default, pinned by a `.nvmrc`/`.node-version`, or hosts a global CLI. It never touches repos, worktrees, `drop/`, transcripts, or the browser caches that agent-browser, Playwright and mmdc run from.
- `btrfs-balance.sh`, Sunday 2:30 and on demand from the health check — data-chunk balance (`-dusage=50 -dlimit=30`) on both filesystems, never metadata. A higher `-dusage` is not an escalation path (header).
- `ram-monitor.sh`, systemd timer every 30 s — logs to the journal only, never ntfy (`journalctl -t roost/ram-monitor`), one process over 3 GB RSS or the processes sharing one command name over 6 GB together: the record of what was big before a kill, which is what health-check pages on. Tests: `tests/ram-monitor.sh`.
- `vision-abuse-watch.sh`, daily 5:30 — ntfy on source IPs never seen before on the Path D inbound.
- `session-daily-brief.sh`, daily 06:40 — a `claude -p` brief of yesterday's sessions, time, usage and commits, sent as plain-text ntfy and archived under `usage/briefs/`. Usage is shown as a share of the weekly cap, never in dollars, and kept separate per login.
- `roughdraft-watch.sh`, daily 07:10 — watches upstream Roughdraft, its npm version and the PRs our fork carries, and sends an ntfy only on change (why the fork exists: the roughdraft skill, "When something is broken"). Needs `gh` authenticated.
- `scheduled-task.sh` / `run-scheduled-task.sh` — run a headless `claude -p` task in a window of the `cron` tmux session. No task is active.

`cron-roost` also carries the weekly travel-VPN audit (`roost-net test`, Sunday 4:00, only while the VPN is on) and the nightly `agent-worktree gc` (3:35), which finishes session worktrees whose Claude died without a SessionEnd.
