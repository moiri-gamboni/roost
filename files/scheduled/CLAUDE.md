# scheduled/ — cron and timer jobs

Deployed to `~/roost/claude/scheduled/`; triggered by `files/cron-roost` unless noted. Every job logs to journald as `roost/<script>` and notifies via ntfy through `_hook-env.sh`. Headers with the full policy: `agents-cleanup.sh`, `btrfs-balance.sh`, `session-daily-brief.sh`, `vision-abuse-watch.sh`, `track-ssh-activity.sh`.

- `health-check.sh` — every 5 min. Checks Caddy, ntfy, Tailscale, cloudflared, disk, and btrfs **unallocated** space on both filesystems (`df %` misses this: unallocated=0 with a full metadata pool is what force-flips the fs read-only, seen 2026-08-19 at df=75%). Below 5GiB it runs `btrfs-balance.sh` itself (cooldown `btrfs-balance-auto`, 24h, under the cron line's flock) and alerts only if still low afterwards, saying whether the balance ran and what it changed; a balance that relocates nothing means the chunks are full of extents snapshots still pin, and the alert says so — pruning snapshots is a policy call, so it is never done automatically. Hard failures bundle into a high-priority `Service health alert`, cooled down by failure-set hash (notify on set change, else at most hourly). The disk check alerts on trend rather than level: above 90% it always reports, and between 80 and 90 only once usage climbs 3 points past the level last reported (baseline in `$HOOK_RUNTIME_DIR/disk-alert-pct`, tracked back down as usage recovers), so a disk parked high stays quiet while a real climb still pages. Soft signals send their own ntfy with per-event cooldowns: sustained swap >3GB (high priority, 1h), pending reboot via `/var/run/reboot-required` (default priority, 7-day reminder, re-arms on a new mtime). Sources `health-check-apps.sh` (from `files/travel/travel-health.sh`) and then `private/health-check-apps-private.sh` if present.
- `auto-update.sh` — Sunday 3am. btrfs snapshot first, ntfy summary after. Safeguards: 7-day release cooldown, major-version guard (blocked and reported). Covers Claude Code, Codex CLI, claude-code-tools, aichat-search, claude-code-transcripts, Go, fnm, Node.js LTS (which strands plain `npm i -g` globals, hence `--prefix "$HOME/.local"` in the global CLAUDE.md), uv, gitleaks, dufs, rclone (pinned selfupdate), PrivateBin, acme.sh, rodney, OS packages. Xray-core is deliberately not here (a restart would hit the in-country user at peak time; it updates on `./deploy.sh` re-runs). Ends by running `disk-cleanup.sh` as a subprocess (sourcing would cut the run short on its `exit 0`) and folding its stdout summary into the weekly ntfy.
- `disk-cleanup.sh` — reclaims regenerable artifacts; runs last inside `auto-update.sh`, so it sees that run's leavings (the Node version the LTS bump just superseded, the Claude Code version `claude update` replaced, the apt archives). `--dry-run` prints the plan and deletes nothing. Removes: superseded fnm Node versions, VS Code Remote server builds, Claude Code versions beyond the newest two, pipenv virtualenvs whose `.project` names a directory that is gone, package-manager caches, dangling Docker layers and build cache, journal above 800M. Three guards keep a Node version alive — it is fnm's `default`, a `.nvmrc`/`.node-version` pins it, or it hosts a global CLI (fnm keeps globals per version, so deleting it uninstalls the tool; these are reported so the tool can be reinstalled with `--prefix "$HOME/.local"`). It also re-anchors dangling `~/bin` corepack shims (`pnpm`/`pnpx`/`yarn`/`yarnpkg`) to fnm's `default` alias rather than a version directory. Never touches the runtime browser caches — `~/.cache/rod` (rodney's shared Chromium, usually running), `~/.cache/ms-playwright` (roughdraft, podcast-studio) and `~/.cache/puppeteer` (mmdc) — nor repos, worktrees, `drop/` or transcripts. `uv cache prune` is skipped rather than forced when a live `uv`/`uvx` process holds the cache lock, which any session's serena MCP server does.
- `btrfs-balance.sh` — Sunday 2:30am, and on demand from `health-check.sh` when unallocated drops below 5GiB. `/` + `/mnt/roost-data`: `-dusage=50 -dlimit=30` data-chunk balance returning slack to the unallocated pool so metadata can keep growing. Data chunks only, never metadata. Logs before/after unallocated. A higher `-dusage` is not an escalation path: measured 2026-08-31 on chunks averaging 92% full, `-dusage=90` relocated 15 chunks and *lost* 0.3GiB of unallocated to the metadata chunk the relocation itself needed.
- `agents-cleanup.sh` — daily 3:30am. Removes `$CLAUDE_CONFIG_DIR/jobs/<id>/` for terminal-state, idle, pid-dead agent sessions idle ≥48 weekday hours, only when the connection-activity marker is ≤24h old (so vacation days don't churn the list). Transcripts, worktrees and branches untouched; sessions stay `--resume`-able. `--dry-run`, `--marker FILE`; env `AGENTS_CLEANUP_IDLE_HOURS`, `AGENTS_CLEANUP_ACTIVITY_HOURS`.
- `track-ssh-activity.sh` — every minute; touches `~/roost/claude/last-connection-activity` if `ss` shows an SSH (22) or ET (2022) connection. The marker agents-cleanup gates on.
- `ram-monitor.sh` — systemd timer, every 30s: any process >3GB RSS, notified PIDs tracked to avoid repeats.
- `vision-abuse-watch.sh` — daily; ntfys never-seen source IPs on the Path D inbound (`/var/lib/roost-travel/vision-seen-ips.txt`).
- `session-daily-brief.sh` — daily 06:40: sonnet-summarized brief of yesterday's sessions, active/attended time, per-session usage (day-sliced est % of the weekly cap + share of the day's tracked burn, grouped per login when several appear, never summed across logins; $ never shown) and commits; ntfy plain text + archive under `usage/briefs/`.
- `roughdraft-watch.sh` — daily 07:10. The global `roughdraft` is built from our fork (global CLAUDE.md, Roughdraft section), so this watches upstream `main`, the npm version and the state of the PRs we carry, and ntfys only on change, saying what it implies for the next rebase. Signature-diffed against `claude/state/roughdraft-watch.state` (one `key=value` per line, matched whole-line so `npm=0.1.1` can't match inside `npm=0.1.10`); a missing state file seeds silently. Needs `gh` authenticated and says so via ntfy if not.
- `scheduled-task.sh` / `run-scheduled-task.sh` — run Claude Code tasks as headless `claude -p` in tmux windows of a `cron` session. No task is currently active (a weekly memory-cleanup task is defined but disabled in `cron-roost`).
